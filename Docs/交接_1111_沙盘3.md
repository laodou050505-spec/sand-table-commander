### 武器握持（重要，中古和哥特都受影响）

原来的毛病：道具 FBX 的根节点带“握点 → 模型中心”的偏移，`DemoFigures.Build` 里补挂点朝向时只转了朝向、没转位置，
所以除了弓以外的武器都偏出手掌（剑偏约 0.42 码）。这个毛病从 10-30 起就在，不是哥特带来的。

现在的做法（`DemoFigures.cs`）：
1. 朝向修正连位置一起转（绕握点转）。
2. 新增 `SnapToPalm`：在握点处垂直于武器长轴截一刀，取最粗的一簇（握柄），平移武器让握柄穿过掌心（蒙在手骨上的顶点的加权中心）。只在垂直于长轴的方向挪，武器伸出去的长度不变。

验证：`Tools/editor_snippets/grip.cs`（用 `cs.py - < 文件` 跑，结果写到 `/tmp/sp2/grip.txt`）量“武器表面到掌心的最近距离 ÷ 身高”。
修之前 20–57%，修之后 36 个兵种的待机和攻击姿势全部 ≤ 2.6%。近景截图（`hands.cs`）也看过，剑、矛、戟、锤、斧、枪都从手掌穿过。
角色的手是张开的（Mixamo 23 根骨骼，没有手指骨），所以看起来是“武器穿在张开的手上”，原型就是这样，不是这次的问题。

## 六、常用命令和这两天踩的坑

- 编译检查：`bash ~/.unity/wartable-tools/compile_check.sh`。跑 C#：`python3 ~/.unity/wartable-tools/cs.py '<代码>'` 或 `cs.py - < 文件`。
- 装配：`WarTable.EditorTools.CoverBuilder.Build(); WarTable.EditorTools.GameSetup.Setup(); EditorSceneManager.SaveOpenScenes();`
- 打包装机：`cs.py 'result.Log(WarTable.EditorTools.WTBuild.BuildApk());'`（约 2 分钟）→ `adb -s PB3A10MGL9240039B install -r -g Builds/<最新>.apk`。adb 在 Unity 6000.5.5f1 的 `PlaybackEngines/AndroidPlayer/SDK/platform-tools/`。旧包和 Burst 调试目录挪进 `~/.Trash/WarTable_cleanup_1110/`。
- 编辑器里走流程的脚本：`Tools/editor_snippets/t.cs`（写 `/tmp/sp2/mode.txt` 为 `begin / fight / throw / check` 后跑）。其余：`each.cs` 逐个近拍兵种，`hands.cs` 拍握持，`grip.cs` 量握持。这些脚本里的输出目录是 `/tmp/sp2/…`，用之前先建目录。
- 棋子只有约 2 cm 高（1 码 = 1 cm）。近拍要把临时台面放大 10 倍，否则相机近裁剪面会切掉模型。
- `WarGame` 里只在 `HeadsetInput()` 分支跑的逻辑，编辑器里测不到。新加的东西要放在通用路径（令牌的 Tick 和事件订阅已挪出来）。
- `/usr/bin/python3` 会报 Xcode 许可错误，用 `/Library/Developer/CommandLineTools/usr/bin/python3`（带 PIL、numpy）。
- zsh 不会按空格拆变量：一串名字要用数组，或者写进文件用 `xargs`。
- Tripo：v2 接口和下载都要带 `User-Agent`，否则被 Cloudflare 挡（403 / 1010）；图片生成并发很低，经常 429，要排队重试。
- 命令里带 `rm -rf` 或复杂的 zsh 展开会被安全检查拦下，临时文件直接覆盖就行，不用删。
- 用户要求所有回复只用简体中文，包括工具调用之间的一句话进度（已被纠正十几次）。
- 这个会话后期频繁中断，原因大概是上下文里截图太多。新会话里少读大图，拼成小图再看。
