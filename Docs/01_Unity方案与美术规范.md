## 场景构成
- **战场保持开阔**（玩法沿用 Three.js 的丘陵野战，打法测试是在开阔地上做的）：两座对称缓丘 + 一条横穿的土路。
- 我军（蓝）在玩家近侧 +Z，敌军（红）在远侧 −Z。Unity x = −原型 x（左右和原型一致）。
- **组合摆放**（用户要求）：布景按一组组小场景摆（`Editor/PropBuilder.cs` 的 Layout 按组写），不是一件件均匀撒开：
  - 左：本岸老橡树丛、渡口（栈桥小船 + 货箱）、石桥、对岸桥头伐木点、对岸松林坡、小丘上的立石圈；
  - 右：村中空地（水井、货摊、木桶、货车）、三座农舍各带柴堆草垛、小教堂 + 院墙、石墙围的羊群牧场、风车 + 三块麦田、远角岩丘废塔；
  - 近侧我军营地：帅帐军旗、营帐围篝火、军械处（兵器架）、坡上箭靶场；远侧敌营：图腾、兽皮帐、两处篝火、尖木栅栏、枯树。
- **不穿模**：菜单 WarTable/5 穿模巡检（`PropBuilder.ClipAudit`）——布景件之间、布景与棋子之间按体素查互相插入，另查出框、压河、压路、压麦田；每次改摆放都要跑到“空报告”。草簇和麦子自动避开布景件占地。
- **会动的东西**：风车叶轮（阵风转速）、河水流动、篝火火苗和烟（`Editor/AmbientBuilder.cs`）、三群绕圈的鸟（`Runtime/BirdFlock.cs`）。
- 程序化部分：地形（`Runtime/BoardMap.cs` 定义高度和地表）、河水（树脂水着色器）、木框（断面扫掠 + 雕花带）、草丛 / 野花 / 麦田 / 篱笆（`Editor/ScatterBuilder.cs`）。菜单 WarTable/1 搭建沙盘、WarTable/2 摆放两军（预览）。
- 地形是自己设计的一张图，玩法阶段模拟层直接读这张图的高度。

## 美术管线
- 先查 ange-embed 素材库；缺的用 **Tripo nano banana**（banana_pro / banana2）出图。
- 模型：**Tripo P2**。流程：参考图（单件、纯色底）→ 四视图 → **白模**（texture=false）→ 审计破面 / 漏面 / 碎片 / 自穿插（`Tools/mesh_audit_p2.py` + 六视图人工看）→ 通过才贴图（以参考图为准）→ 清理、补洞、LOD → 贴图 **≤ 2048、不能糊**（近景渲染核对）。
  - 资产表 `ArtSource/specs.json`，参考图 `ArtSource/Refs/<名>/image.png`，进度 `ArtSource/ModelsP2/<名>/state.json`。
  - 跑：`Blender -b -P Tools/p2_pipeline.py -- run <名…>`，审批 `-- approve / reject`，收尾 `python3 -I Tools/p2_finalize.py <名…>`。
  - Tripo 出图只能串行：`python3 -I Tools/gen_images.py <队列.json>`。
- 精确几何（沙盘框、底座、地形网格）用 Blender / Unity 程序化生成，不交给 P2。
- 真机不开后处理；画面靠材质和光照。
- 主光 `Sun` 在场景顶层（不能放在 EditorOnly 的预览节点下，打包会被剔除），摆沙盘时 TrayRig 让它跟着沙盘转。

## 角色（用户定：沿用原型，原样）

## 画面与性能（10-31）
- **不要“一层雾”、反光不要强**：`Runtime/BoardLook.cs`（挂在沙盘根节点）设全局：边缘光 0、环境光 ×0.75、饱和度 1.04、贴图对比 1.1；`BoardBuilder.Look` 在每个 MiniLit 材质创建时统一：高光上限 0.05（金属 0.4）、暗部色压深。
- **贴图清晰**：模型贴图 Kaiser mipmap、8× 各向异性、三线性、mip 偏移 −0.25；P2 布景 ASTC 5×5，原型角色 / 武器 ASTC 4×4。
- **LOD**：原型角色 / 坐骑减面 30%、武器盾 35%（`Tools/make_demo_lods.py`，骨骼权重不变，低模挂原模骨骼），棋子 LODGroup 0.065（眼前约 55 cm 内用原模）；P2 布景 4 档，LOD3 只给很远的小件（树、灌木在座位距离用 LOD3 会出棱角）；地形 180 格。
- 座位视角（90° 视场）约 53 万三角面：棋子 21 万、布景 22 万、地形 7.8 万、草簇 2.5 万。上机后实测帧率再调。
- 坡上的棋子：落点用地形网格射线（不是高度函数），底座顺坡贴地、人物保持直立。

## 玩法（10-31）
- **模拟层**：原型 TypeScript 模拟逐行移植成 C#（`Runtime/Sim`，命名空间 `WarTable.Sim`，double、与 JS 一致的随机数和遍历顺序）。和原型逐步对照过三条路径（全军冲锋、AI 自动指挥带军令、布阵方案带重排），完全一致。指挥逻辑 `Runtime/Command`（原型 commandLogic / battleCommand）。
- **显示**：`Runtime/Game/BattleView`（每个士兵一枚棋子、箭 / 投矛对象池）、`FigureView`（原型 agentView 的动作选择、坐骑独立、阵亡定格 → 2 秒后沉下 3 cm 消失）、`WarGame`（封面 → 布阵 → 交战 → 结算，0.6 倍速 / 慢动作 / 暂停）。菜单 WarTable/7 装配玩法。
- **地形与平衡**：模拟层的地形（`Sim/BoardTerrain`）只取 `BoardMap.Hills` 里战场上的几座丘陵，按原型公式算；画面上的土路、细碎起伏、岩丘、村庄台地不进模拟（棋子显示仍贴画出来的网格，差几毫米）。
  - 原因：这套模拟对地形微小差别很敏感（同一局起伏差 0.3 码胜负就会翻），把装饰起伏也算进模拟时“无脑全冲”系统性偏强（同样的丘陵，原型 9/20 → 沙盘 15/20）。
  - **选定地形：原型地形种子 1**（`BoardMap.Hills` 前四座）。每种打法 20 局：挂机 0、无脑全冲 9、待敌反冲 14、步弓待敌 + 骑兵包抄 12、骑兵延后 13——三种有章法的打法都胜过全冲。16 套原型地形里多数全冲能赢 14–18 局。
  - 注意：原型文档里“全冲 4/10”是测法的巧合——原型每局用同一个种子同时生成地形和战斗，两者相关；地形固定、只换战斗种子时，全冲平均约 72%。
  - 测法：`Editor/BalanceTest.cs`，五种打法（挂机 / 无脑全冲 / 待敌反冲 / 步弓待敌 + 骑兵包抄 / 骑兵延后）各打 20 局；`EvalTerrainSeed(地形种子)` 用原型 Terrain.open 的丘陵试一套地形。原型地形上 C# 结果和原型完全一致（挂机 1、全冲 4、待敌 6、包抄 6、延后 8 / 10），说明测试本身没写错。10 局样本噪声太大，选地形至少 20 局。
- **头显输入**（`Runtime/XR`，头显上才生效，编辑器里鼠标键盘试玩）：
  - `MRInput`：PICO 手部追踪 + 眼动（照《天底》真机验证过的读法），没有眼动退回头部朝向；`MRRig`：视频透视 + 地面原点。
  - `TrayRig`：手掌平按桌面 1 秒 → 沙盘落到桌上（近边离身体至少 22 cm、玩家一侧朝人）；双手捏住托盘 → 拖 / 转 / 缩放 0.5×–2×。只在封面阶段允许重新按手掌摆放。
  - **头显玩法只靠“看 + 捏 + 拖”**（10-31 用户：不要像电脑上那么繁琐；要注意交互舒适）。电脑版那 20 多条快捷键军令只留作编辑器调试。
    - 看着己方部队（部队本身或它的战旗）捏一下 = 只选这一支，再捏它 = 取消；看着我方帅旗捏 = 布阵时开战、交战时全选。
    - 在沙盘上拖一条线 = 走过去沿线列阵（线长 = 队宽，自动朝敌）；点空地 = 走过去；选中后看着敌军捏 = 冲向那支敌军（远时先列队开过去，12 码内冲锋）。
    - **指挥手势代替按钮**（`Runtime/XR/Gestures.cs`，用户批准）：选中部队后握拳向前一推 = 冲锋，掌心朝下往下一按 = 坚守，掌心朝自己往怀里一招 = 撤退，双手同时握拳前推 = 全军冲锋。只认身前、低于视线、够快够远的动作，1 秒冷却，捏合中的手不认；合成数据测试 `Editor/GestureTest.Run()`（11 项，含 7 个误触反例）。阵型、朝向、放箭、间距全自动。
    - 已有选中时捏在部队上先不判定：松手时没拖开才算点选，拖开了就是划线（从部队脚下往前拖不会误取消选中）。
  - 舒适：手可以搁在桌上 / 身前低处捏（间接拖动，增益 = 落点距离 / 手的距离，上限 4×，不用举臂伸手）；视线短暂移开 0.3 秒内仍算看着刚才的目标（眨眼、眼跳不扑空）；划线时战场自动放慢到 0.35 倍、松手恢复；拖动的手位置平滑 60 ms、终点取松手前 80 ms（手指张开时捏点会跳）；交战中不会因手掌搁在桌上而重新摆托盘。
  - 军令按钮、开始 / 再来一局等交互在 UI 阶段做；代码里军令都走 `BattleCommand.Exec(命令名)`。
